# 营地地图 · 房车露营营地共享平台

一个众包的房车营地地图：用户可以在上面标记营地、上传照片，其他人能看到并核实。
免费用户看点位，会员用户看完整的地址、电话、价格、设施和照片。

## 快速开始

```bash
./start.sh                      # 开发模式（默认 RVCAMP_DEV=1）

# 生产模式：必须设置 PEPPER，否则服务拒绝启动
RVCAMP_DEV=0 RVCAMP_PEPPER=$(python3 -c "import secrets;print(secrets.token_hex(32))") ./start.sh
```

- 用户端：http://127.0.0.1:8000
- 管理后台：http://127.0.0.1:8000/admin（生产用 `RVCAMP_ADMIN_PATH` 改成随机串）
- 日志：`data/logs/rvcamp.log`

## 两个端，同一套密钥体系

| | 用户端 `/` | 管理后台 `/admin` |
|---|---|---|
| 登录方式 | **32 位密钥**（点「免费领密钥」即刻生成） | **管理员密钥**（`ADM` 前缀） |
| 普通用户能否进入 | — | ❌ 后端 403，前端也会拒绝 |

前后台共用 `/api/auth/key/login`，权限差异由数据库 `is_admin` 决定，不靠不同接口区分。
后台路径可通过 `RVCAMP_ADMIN_PATH` 改掉，并支持 `RVCAMP_ADMIN_IP_WHITELIST` 做 IP 白名单。

## 演示数据

演示凭证**在灌数据时随机生成**，不写死在代码里（仓库是公开的，固定凭证等于给每个
部署实例留后门）。跑完 `seed.py` 后看控制台输出，或读 `data/dev_keys.json`：

```bash
python backend/seed.py --reset
```

| | 字段 |
|---|---|
| 用户端密钥（已开通会员） | `user_key` |
| 管理员密钥（`ADM` 前缀） | `admin_key` |
| 应急账号密码 | `admin` / `admin_password` |

本地开发模式下，前端登录框会直接显示这两串密钥、点一下即可填入；生产模式后端不再下发。
想固定成自己好记的，用环境变量指定：

```bash
RVCAMP_SEED_USER_KEY=xxx... RVCAMP_SEED_ADMIN_KEY=ADMxxx... \
RVCAMP_SEED_ADMIN_PASSWORD=xxx python backend/seed.py --reset
```

**快捷入口**：`/#login`、`/#key`、`/#member`、`/#spot-12`（直达某个营地）

> ⚠️ 改过 `RVCAMP_PEPPER` 后所有已发放密钥会失效，需要重跑 `seed.py --reset`。
> 演示数据也依赖当前 pepper，换环境请重新灌入。

## 图片上传的安全设计

UGC 平台的图片上传是最容易出事的地方，这里做了四层防护（`test_upload.py` 有完整验证）：

| 攻击方式 | 防护措施 |
|---|---|
| 把 `shell.php` 改名成 `a.jpg` 上传 | **验文件头魔数**，不看扩展名也不信 Content-Type |
| 上传 HTML 钓鱼页 | 只放行 JPG/PNG/WebP/GIF 四种真实图片格式 |
| 超大文件撑爆磁盘 | 单张限 5MB，超限立即中断读取 |
| 文件名写成 `../../etc/passwd` | **用随机文件名重命名**，彻底丢弃客户端提供的名字 |
| 删除接口传 `?path=../../` | 校验规范化后的路径必须在上传目录内 |
| 删掉别人上传的图片 | 校验 `uploads.uploader`，非本人非管理员返回 403 |
| **照片 EXIF 泄露拍摄坐标** | **重新解码编码，保存时不写 EXIF**，GPS 一并丢弃 |
| 原图 4MB 拖垮列表页 | 生成 480px 缩略图，列表/搜索只加载缩略图 |

实测结果：PHP 木马、HTML 钓鱼页、随机二进制、空文件全部被拦截；路径穿越被重命名为随机串；
带 GPS 的手机照片上传后 EXIF 为空，体积降到原来的 1/10 以下。

## 安全护栏

| 风险 | 处理 |
|---|---|
| 任何人自助开通终身会员 | `mock-pay` 演示支付受 `RVCAMP_ALLOW_MOCK_PAY` 控制，生产默认关闭 |
| 数据库泄露后可离线反推密钥 | `sha256(PEPPER + 密钥)`；**生产缺失 `RVCAMP_PEPPER` 直接拒绝启动** |
| 任意站点跨域调用接口 | CORS 由 `RVCAMP_CORS` 白名单控制，生产留空 = 纯同源 |
| 脚本批量领密钥 / 刷提交 / 刷上传 | 全局写请求限流 + 分接口限流（记在库里，多 worker 也准确） |
| 后台入口被扫到 | `RVCAMP_ADMIN_PATH` 改随机串 + `RVCAMP_ADMIN_IP_WHITELIST` 白名单 |
| 改了数据说不清谁改的 | `audit_log` 记录**改前值 → 改后值** |

> 仍需注意：token 存在 localStorage（XSS 场景下会失守）。生产建议改 httpOnly Cookie，
> 或至少给页面加 CSP。这一项需要前后端一起改，尚未处理。

## 技术要点

## 底图（已精简为单一源）

**只剩 OpenFreeMap。** 其它源全部删除，原因如下（已写进代码注释，防止日后又加回来）：

| 曾经的源 | 删除原因 |
|---|---|
| OSM 官方瓦片 | 政策明确不鼓励收费服务使用；无付费档，可无通知封禁 |
| Esri 卫星影像 | 免费条款要求产品"不产生收入"，会员制站点直接不满足 |
| OpenTopoMap | 镜像条款限定**非商业**用途，月 40 万张以内才算低量 |
| Cyclosm | 捐赠支撑，无 SLA |
| 高德 | 国内源需额外 GCJ-02 纠偏，且本方案走无 Key 旧接口随时可能失效 |

OpenFreeMap 是 OSM 派生数据，但公开实例**免 Key、不限量、明确允许商用**
（样式 MIT，数据 ODbL），由 MapLibre 渲染矢量瓦片，缩放不糊。

### 自建瓦片代理（当前默认，零 Key 零费用）

浏览器**不再直连源站**。所有底图请求走自家域名：

```
浏览器 -> /tiles/ofm/... -> 后端 tileproxy.py -> 上游（默认 OpenFreeMap）
                          ↓
              data/tiles/ 磁盘缓存（每块瓦片只回源一次）
```

`backend/tileproxy.py` 做了五件事：统一出口（源站只见服务器一个 IP）、
落盘缓存、单飞回源（同一块并发只发一个上游请求）、并发闸 + 超时重试 +
404 负缓存、生产环境防盗链（只认本站 Referer）。样式 JSON 里的绝对 URL
会被改写成同源路径，MapLibre 的字体 / sprite / 瓦片全部走代理，不漏一个外链。

运维入口：后台「瓦片缓存」页可看缓存块数、磁盘占用、命中率，并能手动清理。
热门区域可提前预热（等于自建常用区域瓦片库）：

```bash
python deploy/selfhost-tiles/warm_cache.py --bbox 116.0,39.6,116.8,40.2 --minz 10 --maxz 14
```

想彻底和第三方瓦片服务脱钩（断网也能跑），用 `deploy/selfhost-tiles/` 里的
脚本自己切片：Geofabrik 数据 + tilemaker + martin，全程开源免费、无需任何 Key。
上游切换只需一个环境变量（`RVCAMP_TILE_UPSTREAM_OFM`），前端零改动。

#### 踩过的坑：样式里不能写相对路径

代理一开始把样式 JSON 里的绝对地址改成了 `/tiles/ofm/...`，结果**矢量底图整片
不渲染**：MapLibre 在 **Web Worker** 里 fetch 瓦片，而 worker 没有 document base
URL，相对路径会直接抛 `Failed to parse URL`。表现很有迷惑性——栅格底图（主线程
`<img>` 加载，相对路径能用）还在，于是"低缩放只有模糊底色、放大后全白"，
看起来特别像"源站挂了"或"数据里没路"。

现在缓存里存的是相对路径（换域名也能复用），**发给你浏览器之前会补成绝对地址**。
另外 JSON 里的代理地址都带版本参数 `tv=`，改一次 `RVCAMP_TILE_URL_TOKEN`
（或前端 `STYLE_VER`）就能让所有人的浏览器立刻放弃旧样式，不用等缓存过期。

#### 低缩放级别的道路

OpenMapTiles 按级别分层给道路数据：z4 以下几乎没有路，z5-z8 只有寥寥几条
高速/国道。代理会在样式里追加一个 `rv_road_boost` 图层（只在 z3-z10 生效），
把主干道画粗画亮，缩到全国视图也能看到路网骨架；放大后交回原生样式。

### 国内实测数据（2026-10-07，本机 → 源站）

| 指标 | 实测值 |
|---|---|
| DNS + TLS + 首字节 | 0.45 ~ 3.0 秒 |
| 单块 z12 矢量瓦片 | 约 21 KB |
| 连续拉取 30 块 | 全部 200，无触发限流 |
| 响应头 `cache-control` | `public, max-age=315360000`（10 年） |
| CDN | Cloudflare（带边缘缓存） |
| Python urllib 默认 UA | **被挡 403**（源站做了 UA 过滤，浏览器 UA 正常） |

> ⚠️ **每块瓦片 1~3 秒延迟，国内体验偏慢。** 首屏约需 20~30 块瓦片，
> 即使并发加载也要好几秒。这是国内直连境外 CDN 的正常表现，
> 正式运营建议改走合规国内源或自建瓦片（见下节）。

### "不限量"的真实含义

不是合同承诺的无限，而是**没有配额计数器**。它是一条捐赠支撑的公益服务：
- 没有账号、没有 Key → 也就没有按 Key 计费的额度
- 保护手段是自动化的：UA 黑名单 + 按 IP 限流（Cloudflare + nginx），超限返回 429/403
- **没有 SLA**：可能随时变慢、改政策、关停，你也没有付费档可以买来解决

所以它"能用到什么量"取决于你的请求是不是像正常浏览器。
极端情况下：你自己 busy loop 循环拉瓦片，几分钟内就会被限；
如果通过 nginx 代理把全部用户的请求都汇聚到**服务器那一个 IP**，
也更容易触发 —— 这正是为什么上了规模要走缓存代理或自托管。

### 上线建议（按优先级）

1. 开发/演示：默认配置即可（自建代理 + OpenFreeMap 上游，零 Key 零费用）
2. 有小流量：已是默认形态；热门区域跑一遍 `warm_cache.py` 预热，用户打开即本地命中
3. 量大或有断网刚需：`deploy/selfhost-tiles/` 自建离线瓦片（tilemaker + martin）
4. **正式对外运营（尤其收费）：换成有审图号的国内合规底图** —— 见 `frontend/index.html`
   末尾的 `COMPLIANT_CN_BASEMAP` 注释块，放开注释、填上天地图 Key 即可整体替换，
   其余代码无需改动（天地图个人开发者有免费额度，只是需要注册拿 Key）

> 🔴 **合规红线**：面向中国大陆用户提供地图服务，应使用合规底图
> （天地图 / 高德 / 腾讯 / 百度）。OSM 系数据的行政区划着色、
> 台湾与南海诸岛的呈现方式，与中国官方地图规范不一致（缺少九段线等），
> 直接上线存在被责令整改的风险。详见 `docs/运营模型的合规要点.md`。

## 坐标系

国内地图最大的坑。手机 GPS 给的是 WGS-84，国内底图用的是 GCJ-02，
两者在中国大陆相差 **300-800 米**（天安门参考点实测 554.7 米）。

本项目策略：
- **数据库统一存 GCJ-02**，与底图对齐
- 来源是 WGS-84 的数据（GPS、GPX 文件）在入库时转换
- 接口额外返回 WGS-84 和 BD-09 副本，方便第三方接入
- 前端浏览器定位同样做纠偏

`geo.py` 已做自检，往返转换误差 **0.0000 米**。

### 视口查询

```
前端 moveend/zoomend -> 带上 bbox -> 后端只查矩形内数据 -> 260ms 防抖
```

低缩放级别额外做地理网格抽样（zoom≤6 用 0.5° 网格，≤8 用 0.2°，≤9 用 0.08°），
保证任意视口返回量可控，放大地图后自动补全。

### 会员门禁

**在前端隐藏等于没隐藏**。正确做法是后端裁剪响应字段——
免费用户拿到的 JSON 里 `phone` 就是空字符串，抓包也拿不到。
实现见 `app.py` 的 `serialize_spot()`。

### 后台权限隔离

`/api/admin/*` 全部走 `require_admin` 依赖，普通用户的 token 也只能拿到
HTTP 403。实测 5 个后台接口，普通用户访问全部被拒，未登录返回 401。

后台还做了**字段白名单**：`PATCH` 只接受 `name/lng/lat/...` 等业务字段，
尝试修改 `created_by`、`verify_score`、`is_admin` 会被忽略。
